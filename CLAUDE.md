# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за проект

Учебный пет-проект: постепенный переход от Unity/C# к .NET backend-разработке. Трекер просмотренных фильмов на .NET 10 + EF Core + PostgreSQL, растущий по четырём независимым осям (данные, бэкенд, фронт, инфраструктура) — см. `PROJECT_BRIEF.md`.

**Перед тем как что-либо делать в этом репозитории — прочитай `PROJECT_BRIEF.md` целиком.** Там актуальный статус, текущая задача этапа и дорожная карта. Этот файл (`CLAUDE.md`) её не дублирует, потому что статус меняется после каждой закрытой задачи, а `PROJECT_BRIEF.md` — единственный источник истины по прогрессу.

## Режим работы агента — обязательно к соблюдению

Это не общий проект «пиши код по заданию». У проекта явный учебный контракт (раздел «Режим работы агента» в `PROJECT_BRIEF.md`), обязательный для любого агента:

- **Этап 1 (текущий): агент не пишет реализацию за пользователя.** На задачу выдаётся цель, чек-лист шагов и критерий готовности (шаблон — в `PROJECT_BRIEF.md`, раздел «Формат выдачи задачи»); реализует пользователь. Агент проверяет присланный код, указывает на конкретные проблемы, задаёт наводящие вопросы. Подсказка — максимум 1-3 строки, с обязательным объяснением «почему так».
- Задачи выдаются **по одной**, не все сразу.
- **Этап 2+**: можно делегировать EF Core миграции, DTO-мапинг, повторяющийся CRUD по уже установленному пользователем паттерну.
- **Никогда не делегируется** (на любом этапе): границы модулей / что уходит в событие vs прямой вызов, дизайн модели данных, дизайн запросов и их сложность.
- После закрытия задачи — обнови раздел «Текущий статус» в `PROJECT_BRIEF.md` (что сделано, что уточнилось по факту, следующая задача) и отметь чек-лист.

Прежде чем писать хоть строчку реализации по бизнес-логике проекта — свериться, на каком этапе сейчас находится работа (раздел «Текущий статус» в `PROJECT_BRIEF.md`).

## Команды

Проект лежит плоско в корне репозитория (без `.sln`, один `.csproj`).

```bash
dotnet build                    # сборка
dotnet run                      # запуск (http://localhost:5066, https://localhost:7131)
dotnet watch run                # запуск с hot reload
```

Тестового проекта пока нет (юнит-тесты в план этапа 1 не входят).

### EF Core миграции

`dotnet-ef` установлен как global tool (`~/.dotnet/tools`, в PATH).

```bash
dotnet ef migrations add <Name>     # новая миграция
dotnet ef database update           # применить миграции к БД
dotnet ef migrations remove         # откатить последнюю неприменённую миграцию
```

### База данных

PostgreSQL 17 в Docker-контейнере `movietracker-db` (порт 5432). Строка подключения — в `appsettings.Development.json` (ключ `ConnectionStrings:MovieTrackerDb`), пароль учебный/локальный.

```bash
docker exec -it movietracker-db psql -U movietracker -d movietracker
# внутри psql: \d "Movies"   — кавычки обязательны, EF Core создаёт таблицы с регистром как у C#-класса,
# Postgres по умолчанию сворачивает нижний регистр
```

## Архитектура

Текущее состояние — минимальный каркас: `Program.cs` (Minimal API, top-level statements), `MovieTrackerDbContext.cs` (пустой `DbContext`, зарегистрирован через `AddDbContext` с `UseNpgsql`). В `Program.cs` пока остаётся шаблонный эндпоинт `/weatherforecast` из `dotnet new webapi` — будет заменён реальными эндпоинтами по ходу этапа 1.

Архитектура **осознанно не вводится заранее** — это прямое правило проекта («Философия проекта» в `PROJECT_BRIEF.md`): слои, CQRS, mediator-паттерн, модульность появляются только с реальным поводом (вторая сущность, вторая связь, реальная бизнес-логика), а не потому что «так принято». Не предлагай и не добавляй эти слои преждевременно, даже если это выглядит как «best practice» — на этапе 1 это осознанный анти-паттерн для целей проекта.

Плановая траектория усложнения (полная таблица — в `PROJECT_BRIEF.md`, раздел «Дорожная карта»):

| Этап | Бэкенд |
|---|---|
| 1. MVP (сейчас) | Один проект, Minimal API, `DbContext` напрямую в хендлере, без слоёв и mediator |
| 2 | Service-слой + DTO отдельно от EF-сущностей |
| 3 | Модульный монолит (Movies/Users/Lists), CQRS, свой мини-mediator (~20-30 строк, не MediatR — тот перешёл на коммерческую лицензию в 2025) или MediatR Community edition |
| 4 | Cross-cutting: валидация, auth, логирование |
| 5 (опционально) | Hosted background service, вынос модуля в отдельный сервис |

Стек: .NET 10, EF Core 10 (`Microsoft.EntityFrameworkCore.Design`), `Npgsql.EntityFrameworkCore.PostgreSQL`, PostgreSQL. Фронт (React + TypeScript, без стейт-менеджера на этапе 1) появится начиная с задачи 1.5 — отдельного фронтенд-проекта в репозитории пока нет.
